# 三阶段验收

## 1. 程序规则

核查来源覆盖、日期／金额／状态／标识保真、重复与重叠导入、退款抵扣、转账用途及最终逐笔结果。金额按整数分计算，不仅比较总额。

规则状态为 `pass`、`fail`、`pending`、`not_tested`。缺失证据和待审核不算通过；未知用途须等待人工对照答案。

## 2. 独立 API

使用相同数据版本、提示词、模型和参数复核各方案。保留请求／响应及指纹。返回疑点必须引用真实记录；调用失败、格式错误或覆盖不足不得补写通过。

当前对话助手的分析不能代替实际 API 调用；AI 无发现不等于账目完全正确。

## 3. 人工逐条核对与体验

用户检查全部来源及最终去向，确认用途、重复分组与退款关系，形成统一对照答案。实际体验导入、查证、纠错和统计，不以通用审核页替代产品体验。

分别保存首次与修正后结果，记录首次配置时间、日常处理时间、人工修改量、纠错耗时及主观体验。准确性问题解决后，由用户选择方案，不用加权总分替代决策。

## 比较约束

每个候选从空账本开始。原生、配置和外部程序补充能力分别注明；适配器已代做分类／去重时，评价的是组合方案。无法导入或提取证据就如实记录，不编造结果。

规则报告、API 报告、重复导入证据、人工真值及体验记录分别留档；单个 `pass` 不等于三阶段验收通过。
